# Languages

lazymark speaks eight languages: English, Spanish, Brazilian Portuguese (`pt`), French (`fr`), German (`de`), Italian (`it`), Japanese (`ja`) and Simplified Chinese (`zh`). It starts in the language of your system (`LC_ALL`, `LC_MESSAGES`, then `LANG`, as POSIX does) and falls back to English; **Settings → Language** changes it live and `language` in the [configuration](configuration.md) fixes it.

What is translated: the interface (panels, popups, status messages), the key list and the bottom bar, the help of the command line (`lazymark --help`, `lazymark task -h`, `lazymark note -h`, `lazymark paste -h`) and the default Kanban column names. Not translated: error messages of the command line (they stay in Spanish), the output keys of `--json`, and the contents of your notes.

Wide characters (Japanese and Chinese) are laid out cell by cell: the tests check every screen of every language at 120x35 and 80x24 for overflow.

## How the translations were made and reviewed

Spanish and English are written in the code by the maintainer. The other six were drafted by an AI model (Gemini, through the project's support agent) from the English text with a glossary and rules (placeholders, shortcuts and command options stay untouched), and then reviewed by a second, independent request to the same kind of model, which proposed corrections that were applied after checking each one. **No native speaker has reviewed any of them yet.**

| Language | Drafted by | Reviewed by | Native speaker |
|---|---|---|---|
| Spanish, English | the maintainer | the maintainer | yes (Spanish); English not native |
| Portuguese (BR), French, German, Italian, Japanese, Chinese | AI model | a second AI request | **not yet** |

If you speak one of them and something reads badly, please open an issue or a pull request: the translations are plain JSON files in `internal/i18n/catalog/<language>.json`, keyed by the English text.

## For contributors

Every text the interface shows is written as `i18n.T("Spanish", "English")` (or the `ES`/`EN` fields of a key binding). The other languages are looked up in the catalog by the English text. Two tests keep it honest:

- `TestCatalogsCoverEverySourceText`: finds every such text in the code (with `go/ast`) and fails if one is missing from a catalog, if a catalog keeps a text that no longer exists, or if a text is not a fixed string (so it could escape the check).
- `TestCatalogsKeepTheLiteralParts`: a translation must keep the format verbs (`%d`, `%s`), the code in backticks, the command options (`--json`), the variables (`$LAZYMARK_NOTE`), the shortcuts in parentheses (`(W)`) and the line breaks.

`I18N_DUMP=/tmp/keys.json go test ./internal/i18n -run TestDumpKeys` writes the list of texts to translate.
